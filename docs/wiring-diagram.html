ESP32 Controller Wiring

Every net below is read directly from this firmware's pin constants — Config.h, Core_04_Hardware.ino, Core_13_LTEModem.ino, Core_18_RTC.ino, Core_19_RFID.ino — not a generic ESP32 pinout. Reflects a 5-motor build (CFG_MOTOR_COUNT = 5), which is the maximum Core_04_Hardware.ino will now compile — a static_assert rejects 6. The RTC, the RFID reader and the coin acceptor on GPIO33 are implemented in firmware, not just wired here. Every ESP32 pin, including the unused and unusable ones, is accounted for in the complete pin map.

Five channels is the hard maximum. MOTOR_PIN_POOL holds exactly these five and Core_04_Hardware.ino carries a static_assert that refuses to compile CFG_MOTOR_COUNT > 5. GPIO33 used to be M6 and is now the coin acceptor; GPIO14/15 were the pool's M7/M8 slots and are now the RTC's I2C bus. Neither is shared, so there is no silent collision to discover — the build simply fails. GPIO12 stays permanently excluded (boot-strap pin).

Coin acceptor

SignalESP32Note
Pulse outGPIO33counts RISING edges, 5 ms debounce in the ISR
Pull-up3V3external 10kΩ — optional on GPIO33, which unlike GPIO34–39 has an internal pull-up available. Kept because the line was already wired this way.
GNDGNDcommon return

Pulse→value: 1 = Rs 1, 2 = Rs 2, 3–5 = Rs 5, ≥10 = Rs 10; 6–9 pulses are rejected as unrecognised. A burst is complete after 200 ms of silence (3 s safety cap). The interrupt is attached only while the cash screen is showing, so motor switching cannot inject counts into the next sale.

Pin history: GPIO22 → GPIO34 → GPIO36 ("VP") → GPIO35 → GPIO33, which freed up when CFG_MOTOR_COUNT dropped from 6 to 5 and M6 was retired. GPIO35 is now spare.

RFID reader (UART1)

SignalESP32Note
TX → module RXDGPIO22freed from the coin acceptor
RX ← module TXDGPIO34input-only pin — swapped from GPIO36 ("VP") with the coin acceptor, which has since moved on to GPIO35
VCC3V3module is rated 3.0–5.5V
GNDGNDcommon return
Baud192008N1, inverted line levels — the reader idles LOW (RS232), not HIGH. Without the inversion every byte decodes as garbage at any baud rate; this was the reader's entire silent-failure mode.

EHUOYAN YHY5225, 13.56MHz ISO14443A/MIFARE read/write module. Frame protocol (AA BB LEN CMD ... CKSUM, 19200 8N1) and the check-card/read-card command bytes are transcribed from the customer's own working PIC18F8722 reference firmware for this reader — see Core_19_RFID.ino.

I2C address0x68registers 0x00–0x06, BCD. Talked to directly over Wire.h — no RTC library dependency.

DS3231 recommended over a DS1307 — ±2ppm drift vs. ±20ppm, and it keeps time on its onboard CR2032 through a power cycle. Third fallback in the clock chain, after WiFi NTP and LTE NITZ/NTP — see Core_18_RTC.ino.

Spare — free for future use
GPIO35in only—FreePreferred spare for a new input. Freed when the coin acceptor moved to GPIO33. Input-only, no internal pull-ups, so an external one is mandatory on any switch or open-collector source.
GPIO36 (VP)in only—FreeAvoid. Sits directly beside EN on the header; a stray or adjacent connection that briefly pulls EN low holds the whole board in reset. Already hit once on this bench.
GPIO39 (VN)in only—FreeInput-only, same pull-up caveat as GPIO35.
GPIO0in/out—FreeLast-resort spare for a new output — the only free output-capable pin left. It is the boot-mode strap: held low at reset the chip enters flash-download instead of running. Anything wired here must leave it high at boot.
Unusable — never wire these
GPIO12in/out—Leave unconnectedFlash-voltage strap (MTDI), read at every reset and required LOW. An external connection here caused a real, reproducible upload failure on this project — which is why it is excluded from the motor pool by name.
GPIO6–GPIO11——Internal SPI flashBonded to the on-module flash die. Wiring anything here stops the board booting.

19 GPIOs wired to peripherals, 2 more on the USB console, 4 spare, 7 unusable. Physical header positions differ between 30-pin and 38-pin DevKit variants, so this table is ordered by function and GPIO number rather than by position on the strip — match the silkscreen labels on the board in front of you, not a pin count.
